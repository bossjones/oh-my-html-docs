00

Problem & Solution

The habits that made Claude 4 reliable make Opus 5 slower, wordier, and more expensive.

1
Problem
Your prompt is fighting the model
System prompts and CLAUDE.md files stuffed with Claude-4-era guardrails send conflicting messages. Opus 5 burns tokens resolving the contradictions between your rules, your repo docs, and your actual request — before it does any work.
The fix
Delete constraints, trust judgment
Remove rules that pre-empt worst cases the model no longer produces. State the goal and the genuine constraints; let surrounding context (the code, the repo, the request) carry the rest. That's the exact move behind the >80% system-prompt deletion.
prompt 14prompt 18
2
Problem
Answers and documents run long
Opus 5's default responses, agentic narration, and written files all run longer than prior models'. Lowering effort won't fix it — effort controls how much the model thinks, not how much it says.
The fix
Calibrate length explicitly
Length is a prompt-level control now. A short conciseness instruction, a <tone_preference> reminder near the end of a long prompt, a narration cadence, a deliverable-length rule — each is one sentence, and each works.
prompts 01–04
3
Problem
Your scaffolding now compounds
'Double-check your answer.' 'Add a final verification step.' 'Spawn a subagent to review.' Opus 5 already verifies and self-corrects — legacy scaffolding stacks on top of built-in behavior and pays twice for the same assurance.
The fix
Remove it — and cap delegation
Strip explicit verification instructions: removing them cuts wasted tokens with no loss in quality. Where your harness allows subagents, say when delegation is worth it and keep spawn counts low.

The Mental Model

Everything the model sees assembles into one stack. Master the stack and every prompting decision becomes: which layer does this belong in, and does it need to load right now?

LayerWhat belongs thereWhat doesn't
System promptProduct context and operational mode — who the agent is, what it's for.Behavioral micro-rules the model handles by default.
CLAUDE.mdA brief repo purpose + the genuine gotchas (the things that would burn a newcomer).Restating the obvious; long guidance better served as a skill.
SkillsTeam opinions, workflows, and deep guidance — retrieved only when relevant.Everything-upfront dumps; over-constraint outside critical areas.
References@-mentions of specs, mockups, real code. Code beats descriptions — an HTML mockup outperforms design prose.Paraphrases of things you could link or paste directly.
Memorize this

System prompt → CLAUDE.md → Skills → References. Put guidance at the shallowest layer that still loads it only when needed — that's progressive disclosure, and it's the organizing principle of the whole stack. In Claude Code, /doctor will right-size your CLAUDE.md and skills for you.

02

Then → Now

Five paradigm shifts separate Claude-4-era context engineering from the Claude-5 generation. The old habit is on the left. Flip each card for the new rule.

1
Then
Give rules
Explicit guardrails against worst cases: 'default to writing no comments. Never write multi-paragraph docstrings.'
Now
Let the model use judgment
'Write code that reads like the surrounding code: match its comment density, naming, and idiom.' One principle replaces a pile of prohibitions — and adapts to every repo it lands in.
2
Then
Give examples
Usage examples in every tool description, showing the model how it should call things.
Now
Design interfaces
The interface itself teaches usage. Defining a status field as pending | in_progress | completed suggests the whole workflow — no example needed. Enumerations and constraints are the new documentation.
3
Then
Put it all upfront
Load every piece of guidance into the system prompt at session start, just in case it's needed.
Now
Progressive disclosure
Guidance moves into skills the model retrieves when relevant; tool definitions defer-load via search. Organize CLAUDE.md and skills as a tree whose branches load at the right moment — not a warehouse loaded all at once.
4
Then
Repeat yourself
The same instruction duplicated in the system prompt and the tool description, because older models missed it otherwise.
Now
Say it once, in the tool
Tool usage instructions live solely in the tool description. Duplication isn't reinforcement anymore — it's two places for the guidance to drift apart and conflict.
5
Then
Memory by hand
Users hotkeying facts into CLAUDE.md so the next session wouldn't forget them.
Now
Auto-memory
The model preserves relevant memories tied to the work and the user on its own. CLAUDE.md goes back to being what it should be: a small, sharp file of repo gotchas — not a junk drawer of session residue.
03

The Levers

Opus 5 has three real controls — effort, thinking, and context — plus one behavior worth governing: delegation. Everything else is prompting.

Effort — the primary cost dial

LevelWhen to use itWhat you get
low / mediumYour default cost-and-latency control wherever quality holds — use them liberally.Strong quality at a fraction of the tokens and latency.
highThe out-of-box default. Start here, then adjust against your own evals.Full-strength reasoning for everyday hard work.
xhighThe most demanding coding and agentic tasks.Maximum depth — priced accordingly.

Migrating from a prior model? Don't carry effort defaults over — re-run an effort sweep on your own evals (prompt 12).

Thinking — leave it on

  • On by default, and it can only be disabled at effort high or below. The right way to cut cost is lower effort with thinking on — for most tasks that beats thinking-off at similar cost.
  • If you must run thinking-off, two artifacts can appear: tool calls written as visible text (the call never runs, and the leaked text pollutes later turns), and internal XML tags leaking into output.
  • Never instruct the model 'don't think' — that kind of rule increases tag leakage. And don't name thinking tags specifically; the general instruction below works better.
The thinking-off mitigation · one combined instruction
# Add to the system prompt of any integration that must disable thinking:
When you use a tool, you may say a brief sentence first. If no tool can express
what the user asked for, say so instead of guessing. Do not include internal or
system XML tags in your response.

Context & delegation

  • 1M tokens is the default and the max. Instruction following, tool calling, and reasoning stay consistent through the whole window — stop engineering around a small-context model.
  • Opus 5 delegates readily. Great for genuinely independent, sizeable tracks; a cost multiplier on small tasks. Give explicit guidance on when delegation is worth it, or set hard caps (prompt 09).
  • Reviews: it finds real bugs at a high rate with few false positives — but it takes severity filters literally. Ask for everything, then triage (prompt 10).

The Prompt Library

Eighteen ready-made prompts in four tiers, each built to make one Opus 5 behavior visible in a live session. Hit Copy prompt and paste. Prompts marked ★ are run-it-twice experiments — the lesson is in the diff between the two runs.

Tier 1 · Response Shaping

Length and narration are prompt-level controls on Opus 5 — effort won't shorten what the model says. These four instructions are the official calibrations; each pairs the instruction with a small task so you see the effect immediately.

01Dial In Conciseness
The canonical conciseness instruction, applied for the whole session.
02The End-of-Prompt Reminder
In a long prompt, a short tagged reminder near the end reinforces tone better than one more rule at the top.
03Narration Cadence
Opus 5 narrates agentic work readily. Describe the cadence you want instead of saying 'stop narrating'.
04Deliverable Length
Files Opus 5 writes to disk run long too — calibrate documents separately from chat.

Tier 2 · Scope & Trust

Opus 5 verifies its own work, fixes its own mistakes, and will expand a task's scope if you let it. These prompts calibrate how much rope to give it — and prove you can cut the old safety nets.

05Constrain the Scope
The official scope instruction, for narrow tasks you don't want widened, narrowed, or transformed.
06Cut the Safety Net ★
Run-it-twice: your old verification boilerplate vs nothing. Same task, two fresh sessions — compare tokens, tool calls, and outcome quality.
07Corrections That Matter
Opus 5 narrates its self-corrections more than prior models. Limit the narration to corrections that change your decisions.
08Disagree, Then Do It
Give the model a deliberately questionable request and watch it flag the concern in one sentence — then proceed as asked.

Tier 3 · Agentic & Review

Where Opus 5 is strongest — long-horizon coding, code review, vision-driven work — and where the two behavioral traps live: eager delegation and literal severity filters.

09Cap the Subagents
The official delegation guidance. Without it, Opus 5 spawns more readily than prior models — a cost multiplier on small tasks.
10Report Everything, Filter Later ★
Run-it-twice: Opus 5 follows 'only report high-severity issues' literally and under-reports. Ask for everything; triage in a second pass.
11Whole Spec, Then Hands Off
Opus 5 performs best given the complete task specification up front and left to run — it finishes tasks rather than leaving stubs.
12The Effort Sweep ★
One fixed task, run once per effort level (set effort in your harness or API between runs). Find where quality holds and stop paying for more.
13See It, Verify It
Vision peaks when the model can iteratively analyze, crop, and visually verify with tools — cheaper than raising effort.

05

The One Rule

Every pattern in this guide is one move, applied somewhere new:

Delete constraints. Rely on context and model judgment.The >80% system-prompt deletion is this rule, applied without flinching.

  • The definition. A constraint earns its place only if the model, given your context, would otherwise get it wrong. Everything else is scar tissue from older models — and now it costs tokens, adds conflicts, and caps the model's judgment at yours.
  • The stakes. Overconstraining is no longer safe redundancy. Conflicting messages across the system prompt, CLAUDE.md, and the request force Opus 5 to spend its effort resolving you instead of the problem.
The bigger pattern

Modern models thrive on less constraint and more intelligent interface design. Simplify the prompt, structure the context, and let judgment fill the space you cleared. When in doubt: delete it, and let prompt 18 tell you if you were wrong.

The migration tax — what to physically remove

  • Verification scaffolding: 'include a final verification step', 'use a subagent to verify', 'double-check your answer' — removing these cuts tokens with no loss in quality.
  • Don't-think rules: any instruction not to think or reason — it increases internal-tag leakage. Use the general mitigation instead (section 03).
  • Conservative review filters: severity caps in review prompts — they are followed literally and hide real findings.
  • Redundant micro-rules: comment bans, docstring limits, style prohibitions the surrounding code already implies — replace piles of them with one judgment principle.
Honest caveat

None of this means 'no rules ever'. Critical areas — safety, compliance, hard product constraints — still deserve explicit instructions, stated once, at the right layer of the stack. The tax being repealed is on defensive rules: the ones that existed because you couldn't trust the model's judgment. Now you mostly can, and prompt 18 will show you where you still can't.
