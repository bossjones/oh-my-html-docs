00

What Pi is

Most coding agents are products you configure. Pi is a harness you program — a deliberately small core that treats everything else as a TypeScript extension you can write, install, or replace while it runs.

“There are many agent harnesses but this one is yours. Adapt Pi to your workflows, not the other way around.” — pi.dev, front page

Pi is built by Earendil Inc. & contributors (MIT, ~98K stars, created August 2025, commits landing daily) as an AI agent toolkit: a unified LLM API, an agent loop, a TUI library, and the coding-agent CLI this guide is about. The monorepo splits cleanly:

PackageDirectoryWhat it is
@earendil-works/pi-coding-agentcoding-agent/The CLI you install. Interactive TUI, sessions, extensions, skills, themes.
@earendil-works/pi-aiai/Unified multi-provider LLM API — one interface over 15+ providers.
@earendil-works/pi-agent-coreagent/The agent runtime: tool calling and state management.
@earendil-works/pi-tuitui/Terminal UI library with differential rendering.
@earendil-works/pi-telemetry—Vendor-neutral telemetry contracts and schemas.

The minimal-core thesis

Out of the box the agent has four write-capable tools — read, write, edit, bash (plus powershell on Windows) — and three read-only helpers (grep, find, ls), driven by a system prompt around two hundred tokens. There is no built-in MCP client, no built-in subagents, no built-in background tasks: each of those arrives as a package (§04), which is precisely the point. The core stays legible; the surface area is yours to choose.

Four ways to run it

default

Interactive TUI

pi in a project directory. Differential rendering, image paste, fuzzy file refs, a session tree.

one-shot

Print mode

pi -p "…" runs a single prompt and exits — pipeable in and out. The scripting workhorse.

streams

JSON event mode

pi --mode json emits the event stream for programmatic consumers. See docs/json.

embed

RPC mode & SDK

pi --mode rpc speaks JSON over stdin/stdout; the SDK embeds the whole session in your own app.

Design point worth internalizing

MCP support is not in core — it ships as the ecosystem’s #1 package, pi-mcp-adapter, which exposes every MCP server through a single ~200-token proxy tool instead of ~10K tokens of upfront definitions, and reads your existing .mcp.json. Minimalism here is a context-budget strategy, not a missing feature.

01

Quickstart — zero to first session

Three steps: check Node, install, authenticate. Then point it at a repo. Full reference: docs/quickstart.

Prerequisite — Node ≥ 22.19.0

The npm package declares engines.node >= 22.19.0. Check with node --version; see §02 for the recommended way to get there. Stuck on Node 20? A legacy-node20 dist-tag exists (v0.74.2) — older, but it runs: npm install -g --ignore-scripts @earendil-works/pi-coding-agent@legacy-node20.

Install (pick one)

macOS / Linux — the official installer
# pi.dev's first-listed method — no Node/npm state assumed
curl -fsSL https://pi.dev/install.sh | sh
any platform — via npm
# --ignore-scripts: pi needs no lifecycle scripts; skipping them
# shrinks your supply-chain surface. pnpm add -g / bun add -g also work.
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
windows — powershell
powershell -c "irm https://pi.dev/install.ps1 | iex"

First session

five minutes in a real repo
cd your-project && pi          # interactive session, cwd-scoped
> Summarize this codebase          # plain prompt
> @src/main.ts what does this do?  # @ = fuzzy file reference
> !git log --oneline -5            # ! runs shell, output joins context

# one-shot / scripting
pi -p "Summarize this codebase"
cat error.log | pi -p "What is failing?"
pi @README.md "Turn this into a tweet thread"
  • Steer mid-run: just type and press Enter — your message interrupts the agent’s current turn. Alt+Enter queues a follow-up instead; Escape aborts.
  • Editor niceties: Shift+Enter newline, Tab path completion, Ctrl+V paste an image, Ctrl+G open your $EDITOR, !!cmd runs shell silently.
  • Trying it is safe: uninstalling (npm uninstall -g @earendil-works/pi-coding-agent) preserves ~/.pi/agent/ — settings, credentials, and every session survive a reinstall.
02

Recommended setup

The second rung: an hour of configuration that makes Pi feel yours. Node done right, a terminal that passes the keys through, a starter settings file, project context, and the trust model understood.

Node, pinned properly

mise (recommended) — or nvm / fnm
# mise — one tool for node/python/etc., respects .tool-versions
mise use -g node@22
# equivalents:
nvm install 22 && nvm alias default 22
fnm install 22 && fnm default 22
# then verify the floor pi needs:
node --version   # must print ≥ v22.19.0

Terminal & tmux — let the modifiers through

Pi’s editor distinguishes Shift+Enter and Ctrl+Enter from plain Enter — but tmux strips that modifier information by default. Two lines fix it (docs/tmux); see also terminal-setup for your emulator:

~/.tmux.conf — then restart tmux fully
set -g extended-keys on
set -g extended-keys-format csi-u

A starter settings.json

Global settings live at ~/.pi/agent/settings.json; a project’s .pi/settings.json overrides it key-by-key (nested objects merge). A sane starting point (full schema):

~/.pi/agent/settings.json
{
  "theme": "dark",                  // or "light"; auto-detects from terminal bg
  "defaultProjectTrust": "ask",     // ask | always | never — see trust below
  "compaction": {
    "enabled": true,                // defaults shown; tune per model window
    "reserveTokens": 16384,
    "keepRecentTokens": 20000
  }
}

The copy button gives you strict JSON (no comments). Other useful keys: extensions / skills / prompts / themes / packages resource arrays, tool filters, retry/backoff, Ctrl+P model-cycling patterns.

Where everything lives

~/.pi/agent/ # global — survives uninstalls ├── settings.json ├── auth.json # OAuth tokens + keys; values may be "$ENV" or "!cmd" ├── keybindings.json # § 03 ├── trust.json # which projects may load local extensions ├── AGENTS.md # global context, prepended everywhere ├── sessions/ # JSONL session trees, organized by cwd ├── extensions/ skills/ themes/ └── npm/ git/ # where `pi install` puts packages your-project/.pi/ # project — loads only after /trust ├── settings.json # overrides global, key-by-key ├── SYSTEM.md # REPLACES the system prompt entirely ├── extensions/ skills/ themes/ npm/ git/ your-project/AGENTS.md # project context (CLAUDE.md read too; # AGENTS.override.md wins; walked up from parents)

Edit any of these mid-session and /reload applies them live. Context files: docs/settings · sessions: docs/sessions.

The trust model — read this before .pi/ surprises you

Security — project-local code is real code

Extensions run with your user’s full permissions, in-process. So Pi refuses to load a project’s .pi/extensions/, settings, or packages until you approve it once via /trust (recorded in trust.json; the defaultProjectTrust setting governs the prompt). Cloning a stranger’s repo does not hand them your shell — keep it that way: review .pi/ before trusting, and prefer defaultProjectTrust: "ask". Sandboxing options: docs/security · docs/containerization.

Four gotchas, flipped

Every one of these bit a real user (three are from IndyDevDan’s READMEs, §08). Click each card for the fix.

Fix
tmux is eating your modifiers

Without extended-keys + csi-u, tmux makes both indistinguishable from Enter. Add the two lines above to ~/.tmux.conf and restart tmux fully (not just the pane).

Fix
Pi does not auto-load .env

Export keys into the environment before launch (export ANTHROPIC_API_KEY=…, or set -a; source .env; set +a) — or point auth.json at them with "$ENV_VAR" / "!command" values.

Fix
Wrong variable name

Pi reads GEMINI_API_KEY — not GOOGLE_GENERATIVE_AI_API_KEY (the name other SDKs use). Re-export under the name Pi expects.

Fix
The project isn’t trusted yet

Run /trust in that project once. Project-local extensions, settings, and packages stay inert until then — by design.

Sessions are trees

  • Every session auto-saves as JSONL under ~/.pi/agent/sessions/, organized by cwd. pi -c continues the latest; pi -r opens the browser; pi --fork branches an old one; pi --no-session for throwaways.
  • /tree navigates branches in place. When you navigate away from a branch, Pi offers to summarize the abandoned work into a BranchSummaryEntry at the common ancestor — exploration is never wasted context.
  • /export writes standalone HTML or JSONL; /share publishes a GitHub gist. Format spec: docs/session-format.
  • Compaction: when context crosses window − reserveTokens, older turns are LLM-summarized while the newest ~20K tokens stay verbatim; /compact [instructions] triggers it manually with your steer. Details: docs/compaction.

05

Advanced setup: writing extensions

This is the reason to choose Pi. Extensions are plain TypeScript modules loaded in-process via jiti — no build step — with hooks into every event the agent emits. Full reference: docs/extensions.

The contract

~/.pi/agent/extensions/hello.ts — or anywhere, via pi -e
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.on("session_start", async (_event, ctx) => {
    ctx.ui.notify("hello from your first extension");
  });
}
  • Discovery: ~/.pi/agent/extensions/*.ts (or */index.ts) load globally; .pi/extensions/ loads per-project after /trust; pi -e ./file.ts for one session; /reload hot-reloads after edits.
  • Full toolbox on pi: registerTool (TypeBox parameter schemas, streaming onUpdate, custom render), registerCommand, registerShortcut, registerFlag, sendUserMessage, setModel/setThinkingLevel, registerProvider, an inter-extension event bus on pi.events.
  • Full context on ctx: ui (select/confirm/input/notify/custom widgets), getContextUsage(), sessionManager, model, compact(), isProjectTrusted(); command handlers also get fork, navigateTree, waitForIdle, reload.
  • Convention (from disler’s repos): register tools at the top level of the extension function, not inside event handlers.

Worked example 1 — a safety gate in 15 lines

guard.ts — block rm -rf before it happens
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

const FORBIDDEN = [/rm\s+(-[a-z]*r[a-z]*f|-[a-z]*f[a-z]*r)/i, /git\s+push\s+--force/i];

export default function (pi: ExtensionAPI) {
  pi.on("tool_call", async (event) => {
    if (event.toolName !== "bash") return;
    const cmd = String(event.params?.command ?? "");
    if (FORBIDDEN.some((re) => re.test(cmd))) {
      return { block: true, reason: `blocked by guard.ts: ${cmd}` };
    }
  });
}

Shape per docs/extensions — tool_call handlers can block or mutate params. For the production-grade version of this idea, see disler’s damage-control extension in §08.

Worked example 2 — IndyDevDan’s minimal footer

The canonical “smallest complete extension,” from disler/pi-vs-claude-code (extensions/minimal.ts) — a custom footer showing the live model and a context meter:

extensions/minimal.ts — © disler, MIT (quoted with attribution)
import type { ExtensionAPI } from "@mariozechner/pi-coding-agent";
export default function (pi: ExtensionAPI) {
  pi.on("session_start", async (_event, ctx) => {
    ctx.ui.setFooter((_tui, theme) => ({
      render(width) {
        const usage = ctx.getContextUsage();
        const pct = usage?.percent ?? 0;
        const bar = "#".repeat(Math.round(pct / 10)).padEnd(10, "-");
        return [`${ctx.model?.id ?? "no-model"} [${bar}] ${Math.round(pct)}%`];
      }, invalidate() {}, dispose() {},
    }));
  });
}

Note the import: older disler repos use the original @mariozechner/pi-coding-agent package name; new code imports @earendil-works/pi-coding-agent. Try it: pi -e extensions/minimal.ts. Official examples live in the repo at packages/coding-agent → examples/extensions/ (snake.ts, summarize.ts, input-transform.ts).

06

Advanced setup: packages, skills, models, embedding

Turning your extension into a package the whole registry can install; plus skills, themes, local models, and running Pi inside your own programs.

Author & publish a package

A Pi package is just an npm package with the pi-package keyword and either convention directories (extensions/, skills/, prompts/, themes/) or an explicit pi field:

package.json — the manifest
{
  "name": "@you/pi-your-thing",
  "version": "0.1.0",
  "keywords": ["pi-package"],      // ← this is the whole registry submission
  "pi": {
    "extensions": ["./extensions/*.ts"],
    "skills": ["./skills/**"]       // globs; "!pattern" excludes
  }
}

npm publish — that’s it. pi.dev/packages auto-discovers anything on npm carrying the keyword; there is no separate submission step. Users then pi install npm:@you/pi-your-thing or trial it with pi -e.

Skills & prompt templates

  • Skills follow the cross-harness Agent Skills standard: a folder with SKILL.md (YAML frontmatter: name ≤64 chars, description ≤1024, optional allowed-tools, disable-model-invocation). Discovered from ~/.pi/agent/skills/, .pi/skills/, and the shared ~/.agents/skills/ + .agents/skills/ — the same directories other harnesses read, so one skill can serve Pi, Codex, and Claude Code at once. Invoke as /skill:name.
  • Prompt templates (docs/prompt-templates) are lighter — reusable parameterized prompts surfaced as slash commands. Disler points Pi’s prompts setting at his existing .claude/commands directory and reuses everything (§08).
  • Themes (docs/themes): JSON with 51 required color tokens (UI, markdown, diffs, 9 syntax, 7 thinking-level borders); hot-reloads while you edit; --use-theme light or the theme setting to switch; an export section skins /export HTML.

Local & custom models

~/.pi/agent/models.json — Ollama example
{
  "providers": {
    "ollama": {
      "baseUrl": "http://localhost:11434/v1",
      "api": "openai-completions",   // or anthropic-messages / google-genai
      "models": [{ "id": "qwen3:30b", "contextWindow": 262144 }]
    }
  }
}

Works for LM Studio, vLLM, and any OpenAI-/Anthropic-/Google-compatible endpoint (docs/custom-provider, docs/models); /llama is the quick path. Extensions can also pi.registerProvider at runtime.

Embed Pi in your own program

the SDK in eight lines
import { createAgentSession, SessionManager, ModelRuntime } from "@earendil-works/pi-coding-agent";

const session = await createAgentSession({
  sessionManager: SessionManager.inMemory(),
  modelRuntime: await ModelRuntime.create(),
});
session.subscribe((event) => console.log(event.type));
await session.prompt("Summarize this repository");

Shape per docs/sdk — which also covers defineTool(), createCodingTools, steering and follow-ups. For process-level integration instead, --mode rpc (docs/rpc) speaks JSON over stdin/stdout and --mode json (docs/json) streams events — that’s the seam IndyDevDan’s observability stack taps.

VS Code & Cursor setup for extension authors

Pi executes your TypeScript directly through jiti — tsc never runs. The editor setup below exists purely so imports resolve, types flow, and squiggles are honest. Cursor inherits all of it unchanged.

The extension-project recipe

my-pi-extension/ ├── package.json # devDeps give the editor types; pi never builds this ├── tsconfig.json # diagnostics only — noEmit ├── .vscode/ │ ├── settings.json # use the workspace TS version │ └── extensions.json # recommend the essentials ├── node_modules/ # npm install --ignore-scripts; pi picks it up automatically └── index.ts # export default function (pi: ExtensionAPI) { … }
package.json
{
  "name": "my-pi-extension",
  "private": true,
  "devDependencies": {
    "@earendil-works/pi-coding-agent": "^0.84.0",  // ExtensionAPI, ExtensionContext
    "typebox": "^1.0.0",                           // tool parameter schemas
    "@types/node": "^22.0.0",
    "typescript": "^5.6.0"
  }
}

Then npm install --ignore-scripts. Real runtime deps (an npm lib your extension imports) go in dependencies — Pi resolves them from the extension folder’s node_modules/ (it walks parents too). Add @earendil-works/pi-tui if you render custom widgets, @earendil-works/pi-ai for StringEnum.

{
  "compilerOptions": {
    "target": "ES2022",

    "noEmit": true,                // jiti executes the .ts — tsc only diagnoses
    "skipLibCheck": true,
    "types": ["node"]
  },
  "include": ["**/*.ts"]
}

The inner loop

Edit index.ts in VS Code/Cursor → in the running Pi session, /reload → behavior updates in place. For a scratch session against a work-in-progress file: pi -e ./index.ts. No watch task, no bundler, no dist folder — the .ts file is the artifact. Study the official examples/extensions/ in the repo when stuck; contributing to Pi itself is documented at docs/development.

08

IndyDevDan on Pi

IndyDevDan (disler on GitHub, agenticengineer.com) has built the deepest public body of Pi work outside the core repo — six repositories that read as a masterclass in what “the harness is yours” actually buys you.

Claude Code is batteries-included behind a ~10K-token guardrailed prompt. Pi is four tools behind a ~200-token prompt — and every battery is a TypeScript file you can read, fork, or replace. — paraphrasing COMPARISON.md, disler/pi-vs-claude-code (Pi v0.52.10 snapshot, Feb 2026)
the playground

pi-vs-claude-code

18 extensions · Bun ≥ 1.3.2 · videos: Pi: The Only Claude Code Competitor · Pi to Pi

“Hedging against the leader in the agentic coding market.” Highlights: damage-control.ts (real-time bash/path safety auditing via tool_call + a YAML rulebook), coms.ts/coms-net.ts (Pi-to-Pi messaging over Unix sockets and an HTTP/SSE hub), agent-team.ts (dispatcher-only orchestrator with a grid dashboard), cross-agent.ts (registers your .claude/, .gemini/, .codex/ commands inside Pi), 11 custom themes, and the COMPARISON.md / PI_VS_OPEN_CODE.md essays. Run any of them: pi -e extensions/<name>.ts.

observability

pi-agent-observability

Bun + SQLite + SSE · video: watch

A drop-in telemetry extension (pi -e extension/pi-observability.ts, ~800 lines) streams the full 16-event lifecycle — with batching, backpressure and retries — into a local Bun/SQLite server with three views: single, swimlane, race. Thesis: measure the performance–speed–cost trifecta. Its package.json demonstrates the "pi": {"extensions": […]} registration convention.

multi-model

fusion-harness

videos: V2 · V1

“Fuse 2–5 frontier models instead of racing them. AND, not OR.” One architect, one primary builder, up to three secondaries — opinions, fusion, debate, coordinated implementation — under a single-writer lease so only one model ever writes. Declarative YAML model stacks; clean-room child sessions via --no-extensions; /fh-* command family; 34 deterministic tests that cost zero API calls.

verification

the-verifier-agent

video: watch

A two-agent system: your interactive Builder Pi, plus an input-locked Verifier Pi in a sibling window that the builder doesn’t know exists. The verifier tails the builder’s session JSONL over a 0700 Unix socket, holds a read-only toolset, and owns exactly one write path — verifier_prompt, delivered as a follow-up. Fails three times → escalates to you. “Structurally un-promptable”: fix the persona, never the instance.

safety

bash-damage-from-within

Claude Code + Pi, side by side

“5 levels to stop your agent from destroying production” — the same defense-in-depth bash ladder implemented twice, claude-code/level-1..5/ mirrored by pi/level-1..5/. The cleanest single artifact for comparing how the two harnesses express identical guardrails.

benchmarking

live-bench

video: watch

A LAN-only live dashboard racing local models (M5 Max vs M4 Max, Qwen 3.5 / Gemma 4, GGUF vs MLX) — with Pi as the driver of the agentic coding benchmark: 6 tasks × 3 models, measuring wall time, correctness, token efficiency, and tool calls.

The doctrine, in five lines

  • Measure the trifecta — performance, speed, cost. “If you don’t measure, you can’t improve.” (The observability stack exists to make this trivial.)
  • AND, not OR — stack models instead of picking one; fusion, councils, and Pi-to-Pi coms are all this idea wearing different clothes.
  • Spend tokens to save time — a verifier agent watching your builder costs tokens and repays them in caught failures.
  • Templated engineering — “build the system that builds the system”: fix the prompt/persona/skill, never hand-patch the running instance.
  • Hedge the vendor — pi-vs-claude-code’s stated purpose. A ~200-token, 4-tool, fully hookable harness is the hedge.
Runtime note — Bun vs Node

Dan’s repos standardize on Bun (≥ 1.3.2 in pi-vs-claude-code) plus just as the task runner — while Pi itself requires Node ≥ 22.19.0. You need both worlds to run his stacks: Node for Pi, Bun for his servers and scripts. His READMEs are also the source of two gotchas already flipped in §02: Pi doesn’t read .env, and Gemini wants GEMINI_API_KEY.

Open questions this guide answered (yes/no)

Nine decisions taken while building this page, each phrased yes/no with the working assumption. Disagree with one? The repo’s plan file (specs/pi-harness-guide.html) shows exactly what flipping it changes.

Q1 — Echo pi.dev’s paper-and-ink identity instead of the library’s dark-guide theme?
Yes. pi.dev is graph-paper light with serif-italic display; matching it makes this page read as “Pi” at a glance. The dark terminals-on-paper treatment keeps code legible.
Q2 — Lead the quickstart with the curl installer rather than npm?
Yes. It’s pi.dev’s own first-listed method and assumes nothing about your Node state. npm (with --ignore-scripts) and PowerShell follow immediately.
Q3 — Recommend mise for Node version management?
Yes, softly. One blessed copy-paste path; nvm/fnm one-liners included. The hard floor is Pi’s engines.node >= 22.19.0 either way.
Q4 — Ship diagrams as inline SVG rather than generated images?
Yes. Inline SVG is self-contained, crisp at any zoom, printable, and palette-synced by construction — the page makes zero image requests beyond its favicon.
Q5 — Profile all 12 packages AND bless a smaller starter stack?
Yes. Twelve equal-format cards ordered by downloads for browsing; four packages blessed in §04 so day one isn’t a choice paralysis exercise.
Q6 — Include the Pi-vs-Claude-Code table although its source snapshots Pi v0.52.10?
Yes, clearly dated. It’s the sharpest articulation of why Pi’s minimalism matters. It’s presented as disler’s argument with a verify-before-relying caveat, not silently updated.
Q7 — Plain links for IndyDevDan’s videos, no embeds?
Yes. Iframes and remote thumbnails would break the self-contained rule and add tracking. Links keep the page offline-safe.
Q8 — Ship the VS Code guidance as copyable snippets rather than committed .vscode files?
Yes. The editor setup belongs to your extension repos, not to the docs site hosting this page. §07 gives complete files to paste.
Q9 — Title this “Pi — The Coding Harness”?
Yes. “Harness” is Pi’s own word for itself, and the framing the guide’s requester used. “Pi Coding Agent” remains in the metadata for search.
