The one-line verdict

These are the same product category, converged. Codex is the stricter one — it separates sandbox from approvals, gates hooks behind a trust hash, and makes you opt into write access in CI. Claude Code is the broader one — three times the hook events, per-tool permissions, system-prompt control and checkpointing. Neither is a subset of the other, but Codex’s hook events are a literal subset of Claude Code’s, name for name.

01

Two Agents, One Shape

Before the tables: the mental model. Both products decompose into the same six layers. Learn the layer, and the vocabulary swap is mechanical.

A terminal coding agent in 2026 is six things stacked: a context layer (an instruction file the model reads), a config layer (settings the runtime enforces whether the model cooperates or not), a capability layer (skills and MCP servers), a delegation layer (subagents), an automation layer (lifecycle hooks), and a safety layer (sandbox plus approvals). Codex and Claude Code both have all six. They disagree about file formats, directory names, and where one dial ends and the next begins — and almost nowhere else.

OpenAI publishes the migration table itself. /import in the Codex CLI reads a Claude Code installation and converts it, and the docs spell out every destination. learn.chatgpt.com/docs/import — “What ChatGPT can import”

On models and plans

Both split “which model” from “how hard it thinks.” Codex names models gpt-5.6 (default for demanding work), gpt-5.6-terra (faster, cheaper) and gpt-5.6-luna (fast, narrow), with a separate model_reasoning_effort taking ultra, max, xhigh, high, medium, low. Model availability is gated by subscription tier on both sides and moves faster than this page can track — check /model in the live tool rather than trusting any written comparison, including this one.

The path that will catch you

Everything else in Codex lives under ~/.codex. Skills do not. They live at ~/.agents/skills globally and .agents/skills in a repo — Codex follows the vendor-neutral agent-skills convention rather than namespacing them under its own product directory. If you mkdir ~/.codex/skills out of habit, nothing loads and nothing warns you.

Precedence, highest first

Codex: CLI flags and -c overrides → project .codex/config.toml (root down to cwd, closest wins, trusted projects only) → profile file via --profile → ~/.codex/config.toml → /etc/codex/config.toml → built-in defaults.

Claude Code: managed settings → CLI flags and local settings → project settings.json → ~/.claude/settings.json. Array settings such as permissions.allow combine across scopes; scalar settings such as model take the most local value.

Three invocations, side by side

Claude Code
# headless, edits allowed, JSON out
claude -p "fix the failing test" \
  --permission-mode acceptEdits \
  --output-format stream-json

# resume the last session here
claude --continue

# scaffold the instruction file
claude
> /init
Codex CLI
# headless, edits allowed, JSONL out

  --sandbox workspace-write \
  --json

# resume the last session here

Read this before you script anything

codex exec defaults to a read-only sandbox. A script ported from claude -p that expects to write files will run, report plausible-sounding work, and change nothing on disk unless you pass --sandbox workspace-write. Codex also requires a Git repository — “Codex requires commands to run inside a Git repository to prevent destructive changes” — overridable with --skip-git-repo-check.

Your Shift+Tab reflex does not survive the move

In Claude Code, plan mode is a permission mode that you cycle with Shift+Tab alongside default, acceptEdits, auto and bypassPermissions. In Codex, plan mode is the /plan command and permissions are a separate /permissions surface. There is no documented Shift+Tab plan toggle. If you are used to tapping Shift+Tab twice before a risky task, build a new habit or you will run the task unplanned.

A Codex trick with no Claude equivalent

“When a chat is already running, you can type a slash command and press Tab to queue it for the next turn.” Codex parses queued commands when they run, so menus and errors appear after the current turn finishes. Handy for lining up /compact behind a long task.

Blocking works the same way in both: return {"hookSpecificOutput":{"permissionDecision":"deny","permissionDecisionReason":"…"}}, or exit 2 and write the reason to stderr. Codex adds statusMessage, additionalContextLimit (default 2500 tokens; 0 passes the full context), async for background hooks, and commandWindows for a Windows-specific override.

Codex will not run your hook until you trust it

“Before a non-managed command hook can run, Codex requires you to review and trust the exact hook definition. Codex records trust against the hook’s current hash, so new or changed hooks are marked for review and skipped until trusted.” Use /hooks to review and trust. Every time you edit a hook, its hash changes and it stops running until you re-trust it — which looks exactly like a broken hook. Claude Code has no such gate.

Custom agents: markdown vs TOML

.claude/agents/reviewer.md

.codex/agents/reviewer.toml
name = "reviewer"
description = "Reviews for correctness and security."
model = "gpt-5.6-terra"
model_reasoning_effort = "high"
sandbox_mode = "read-only"

Codex requires exactly three fields — name, description, developer_instructions — and lets you add any config.toml key on top, including sandbox_mode and mcp_servers. Codex identifies the agent by its name field, not its filename, and a custom agent whose name collides with a built-in (explorer, worker, default) takes precedence. The docs are candid that this “can feel heavier than a dedicated agent manifest, and the format may evolve.”

Runtime overrides beat the agent file

“Codex also reapplies the parent turn’s live runtime overrides when it spawns a child. That includes sandbox and approval choices you set interactively during the session, such as /permissions changes or --yolo, even if the selected custom agent file sets different defaults.” So a sandbox_mode = "read-only" reviewer agent does not stay read-only in a --yolo session.

06

Permissions & Safety

The deepest architectural split in this guide. Claude Code gives you one ordered dial. Codex gives you two independent axes, plus a scripting language for command policy.

Codex is explicit about the separation: “The sandbox defines which files and network resources ChatGPT can access. Approvals determine when ChatGPT pauses before an action.” And critically: “Changing who reviews a request doesn’t expand the sandbox.” Claude Code folds both concerns into a single permission mode.

Rules: a policy engine, not a config list

~/.codex/rules/default.rules — Starlark
# Prompt before running `gh pr view` outside the sandbox.
prefix_rule(
    pattern = ["gh", "pr", "view"],
    decision = "prompt",          # allow | prompt | forbidden
    justification = "Viewing PRs is allowed with approval",
    match = [                     # inline unit tests, validated at load
        "gh pr view 7888",
        "gh pr view --repo openai/codex",
    ],
    not_match = [
        "gh pr --repo openai/codex view 7888",  # prefix must match exactly
    ],
)

Nothing in Claude Code is shaped like this. The closest equivalent is a list of permission strings in settings.json. Codex gives you a sandboxed Python-like language, a three-level decision lattice where forbidden > prompt > allow, inline tests that run when the file loads, and a checker you can run in CI. Rules are marked experimental and may change.

The splitting behaviour is the subtle part. When a shell script is a linear chain of plain words joined by &&, ||, ; or |, Codex parses it with tree-sitter and evaluates each command against your rules, applying the most restrictive result — so allowing git add does not silently allow a destructive command chained behind it. When the script uses redirection, substitution, variables, wildcards or control flow, Codex refuses to interpret it and evaluates the whole thing as one opaque ["bash", "-lc", "<full script>"] invocation instead.

Both yolo flags mean the same thing. Treat them the same way.

--dangerously-skip-permissions and --dangerously-bypass-approvals-and-sandbox / --yolo disable the safety layer entirely. Codex’s own table describes the effect as “No sandbox; no approvals (not recommended).” Use them only inside a container or a disposable VM — never on a machine holding credentials you care about. The short --yolo alias makes it easier to type than its Claude counterpart, which is precisely the risk.

Do not set the key job-wide

Straight from the Codex docs: “Do not set OPENAI_API_KEY or CODEX_API_KEY as a job-level environment variable in workflows that check out or run repository-controlled code. Build scripts, tests, dependency lifecycle hooks, or a compromised action in the same job can read those environment variables.” Set it inline on the single codex exec invocation, or let openai/codex-action proxy it for you. The same threat model applies to ANTHROPIC_API_KEY; only Codex’s docs spell it out.

Switching Gotchas

Eight Claude Code habits that fail quietly in Codex. Each card states the habit; flip it for what actually happens and the fix.

01
The habit
You port claude -p to codex exec and expect it to edit files.
The script runs, reports plausible work, and exits clean.
What happens
codex exec is read-only by default.
Nothing was ever going to be written. Add the sandbox flag explicitly.
--sandbox workspace-write
02
The habit
You tap Shift+Tab to enter plan mode before a risky task.
Nothing visible changes, so you type the prompt anyway.
What happens
Plan mode is a command, not a permission mode.
Codex separates planning from permissions entirely. There is no documented Shift+Tab cycle.
/plan/permissions
03
The habit
You drop a skill into ~/.codex/skills/.
Everything else Codex owns lives under ~/.codex, so this is the obvious guess.
What happens
Skills live outside the Codex home directory.
Codex follows the vendor-neutral agent-skills convention. Nothing warns you about the wrong path.
~/.agents/skills.agents/skills
04
The habit
You tweak a hook script and re-run, the way you would in Claude Code.
The hook fired a minute ago. Now it does not.
What happens
Trust is pinned to the hook’s hash.
Any edit invalidates trust and the hook is skipped until you re-review it. Claude Code has no equivalent gate.
/hooks
05
The habit
You reach for --allowedTools to lock a run down.
It is the first thing you configure in every Claude Code automation.
What happens
There isn’t one, because Codex gates commands, not tools.
Filesystem and network go through the sandbox; shell commands go through Starlark rules. Only MCP tools get allow/deny lists, and those live in config.
--sandbox.rulesenabled_tools
06
The habit
You write a 400-line AGENTS.md, the way your CLAUDE.md grew.
Claude Code loads long files in full and merely warns that adherence may drop.
What happens
Codex stops adding files at 32 KiB.
The cap is enforced, not advisory, and it applies to the combined chain. Raise the limit or split guidance into nested directories.
project_doc_max_bytes
07
The habit
You give a reviewer subagent sandbox_mode = "read-only" and assume it is contained.
You started the session with --yolo because you were moving fast.
What happens
No. The parent’s runtime override wins.
Codex reapplies live session overrides to spawned children “even if the selected custom agent file sets different defaults.” The agent file is a default, not a ceiling.
don’t rely on agent-file sandboxing
08
The habit
You port a custom slash command from .claude/commands/deploy.md.
You look for the matching Codex directory and find nothing.
What happens
They become skills — on both sides.
Codex deprecated custom prompts outright; Claude Code says commands and skills “are now the same mechanism.” /import performs exactly this conversion for you.
SKILL.md/import

Read these two sections together

Codex is deeper on policy and containment: a real rules language, hash-pinned hook trust, named profiles, enforced caps, schema-validated output. Claude Code is deeper on surface area and recovery: three times the hook events, per-tool permissions, system-prompt control, checkpointing, run budgets. Which one is “safer” depends entirely on whether your risk is an agent doing the wrong thing or an agent doing the right thing badly.

Two things to know about these sources

Fetch with -L. Every developers.openai.com/codex/* URL answers a 308 redirect; without -L you get the string Redirecting… and a false negative.

The per-page Markdown twins have holes. Read codex-manual.md for anything tabular.
