Purpose

Build a single self-contained standalone HTML field guide — “Codex CLI vs Claude Code” — that lets an engineer fluent in Claude Code become productive in OpenAI’s Codex CLI immediately. The guide is a set of conversion tables anchored on Claude Code concepts: context and config files (CLAUDE.md ↔ AGENTS.md, settings.json ↔ config.toml), CLI flags, slash commands, customization surfaces (skills / subagents / hooks / MCP / plugins), the permission and sandbox model, and headless / CI / GitHub Actions — closing with an honest accounting of what each agent has that the other doesn’t. Every claim is grounded in doc pages harvested via curl pipelines that also ship as reusable justfile recipes. The finished doc is imported into oh-my-html-docs and validated end-to-end with playwright-cli. This is the third guide in the family, after opus-5-mastery (coral) and copilot-cli-vs-claude-code (purple).

Problem

Codex CLI and Claude Code have converged on the same shape — interactive TUI, plan mode, headless mode, MCP, skills, subagents, hooks, plugins — but every concept wears a different name, lives in a different file format, and takes a different flag. An engineer moving between them has to reconstruct the mapping from two separately-organized doc sites. Worse, the obvious guesses are wrong in ways that fail silently: codex exec defaults to a read-only sandbox, so a ported claude -p script runs, reports plausible work, and writes nothing; Codex skills live at ~/.agents/skills, not under ~/.codex, so a skill placed by analogy never loads; editing a Codex hook invalidates its trust hash and it stops firing with no error. None of these surface as failures — they surface as an agent that seems to work.

Solution

Author a new standalone bundle in the house dark identity (OpenAI green #10A37F on the shared #0A0C10 surface family) reusing the copilot-cli-vs-claude-code skeleton verbatim: .matrix verdict tables with the Codex column tinted (the subject under examination), plain conversion tables ordered Concept | Claude Code | Codex CLI | Notes, flip-card switching gotchas, terminal-chrome code blocks, and a copy-button cheat sheet of equivalent command pairs. Research first: harvest ~50 doc pages into a committed research/ directory using two new curl pipelines promoted to just codexdocs / codexdoc, then resolve every uncertain mapping in a citation-backed mappings.md before writing a glyph — no “doesn’t have it” claim without a doc sentence. Then import via scripts/new_doc.py, capture a preview screenshot, and validate with the repo’s playwright-cli recipe.

Questionables

Open questions, phrased yes/no where possible. Each carries the assumption the build proceeded on.

Q1 — Keep the comparison strictly 2-way (Claude Code ↔ Codex), no Copilot column? (yes/no)

Answered by the user: yes. A third column would widen every table past comfortable reading and would require re-verifying every Copilot cell against August-2026 docs rather than the July snapshot. The sibling guide already covers Copilot.

Q2 — Commit the 1.9 MB codex-manual.md whole rather than splitting it? (yes/no)

Assumption: yes. It is the only source with rendered flag, command and config tables — the per-page Markdown twins leave 29 MDX <ConfigTable/> placeholders in developer-commands.md alone. Splitting risks silent loss; the research directory is already excluded from lint and is not built by MkDocs.

Q3 — Enforce “no ‘not documented’ glyph without a citation; uncertain → partial” even where it makes the matrices look less decisive? (yes/no)

Assumption: yes. Every “tool X lacks feature Y” cell is a falsifiable claim. Codex ships fast and its docs are newer than Claude Code’s, so absence of documentation is weak evidence of absence of feature. The footer and §12 both state that “—” means “not documented at harvest date.”

Q4 — Ship v1 with zero embedded images (placeholders as HTML comments)? (yes/no)

Assumption: yes, matching both sibling guides. The doc is table-first. The card’s preview PNG is separate and is captured.

Q5 — Call scripts/new_doc.py directly rather than just add? (yes/no)

Assumption: yes. Both prior plans recorded that the just add recipe drops quoting on multi-word titles. Fixing the recipe’s quoting remains a worthwhile follow-up, but is out of scope here.

Q6 — Accept that learn.chatgpt.com/guides/best-practices.md 404s despite being listed in the index? (yes/no)

Assumption: yes. Only the HTML page resolves; the Markdown twin returns 404. It is a soft “getting started” guide whose substance is covered by codex-manual.md, and nothing in the doc cites it. Noted in the corpus caveats of mappings.md.

Q7 — Is one accent (OpenAI green) safe next to the existing mint --ok verdict glyph? (yes/no)

Assumption: yes, with a tweak. #10A37F and #4FE3A3 are both greens. Rather than change the shared --ok token, the verdict glyphs got a font-size:1.05em bump so they read as lighter and larger than surrounding accent text. Verified on the rendered screenshot.

Findings that shaped the doc

  • Codex hook events are a strict, name-identical subset of Claude Code’s. All 11 — PreToolUse, PermissionRequest, PostToolUse, PreCompact, PostCompact, UserPromptSubmit, SubagentStart, SubagentStop, SessionStart, SessionEnd, Stop — exist on both, with a compatible JSON schema and the same exit-code-2 blocking convention. This became the guide’s headline and its lead stat.
  • OpenAI publishes the conversion table itself. The /import page documents a 9-row Claude Code → Codex destination map. Featured as a pull quote and a table in §01 — it is the strongest possible citation for the guide’s premise.
  • Codex skills do not live under ~/.codex. They are at ~/.agents/skills and .agents/skills. This is the single most surprising path in the corpus and earned its own callout plus a gotcha card.
  • Permissions do not map one-to-one. Claude Code has one ordered mode dial; Codex has two independent axes (--sandbox × --ask-for-approval) and states explicitly that “changing who reviews a request doesn’t expand the sandbox.” The guide composes rather than translates.
  • Codex has a policy language. .rules files are Starlark with prefix_rule(), a forbidden > prompt > allow lattice, inline unit tests, tree-sitter splitting of compound commands, and an offline checker (codex execpolicy check). Nothing in Claude Code is shaped like it.
  • Both products deprecated custom slash commands in favour of skills, independently. Codex’s custom-prompts page says “Use skills for reusable prompts”; Claude Code says commands and skills “are now the same mechanism.”

Design decisions & rejected alternatives

  • Codex column tinted in every matrix. The reader baseline is a Claude Code user examining Codex, so Codex is the subject under examination. Tint strengthened from the skeleton’s .07/.12 to .10/.20 after a screenshot showed the original was too subtle to read as “tinted.”
  • Rejected: changing --ok to avoid the green-on-green collision. That token is shared across the guide family. Bumping glyph size instead keeps the palette consistent and solved the legibility issue.
  • Rejected: redesigning the skeleton. The copilot guide is already playwright-proven. Re-skin and re-content only; the JS block is copied byte-for-byte, including its hardcoded 'Copy pair' restore label — which is why every copy button carries exactly that text.
  • Research is committed, not scratch. A comparison doc needs auditable provenance that survives the session and the vendors’ next docs reorganization.
  • Dependencies: none added. The guide stays dependency-free self-contained HTML (Google Fonts links only, matching both siblings).
