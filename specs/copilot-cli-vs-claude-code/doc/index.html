01

Two Agents, One Shape

Both tools are the same species: a terminal agent that reads instruction files, asks permission per tool, extends via MCP/skills/plugins, and runs headless in CI. Most concepts translate one-to-one — learn the vocabulary and you know both tools.

ConceptClaude Code says…Copilot CLI says…
Repo instruction fileCLAUDE.mdAGENTS.md / .github/copilot-instructions.md and it reads CLAUDE.md too
Agent home directory~/.claude (CLAUDE_CONFIG_DIR)~/.copilot (COPILOT_HOME)
“Skip all prompts”--dangerously-skip-permissions--allow-all-tools / --yolo
Mode wheel (Shift+Tab)permission modes default → auto-accept → planinteraction modes standard → plan → autopilot
Delegated specialistsubagentcustom agent (subagents; /fleet runs them in parallel)
Headless runprint mode (-p)programmatic / prompt mode (-p)
Undo the last turn/rewind (checkpoints)/undo (alias /rewind)
Session memoryauto memoryCopilot Memory
Cloud hand-offweb/background sessions (& Actions app)/delegate → Copilot cloud agent
Reasoning depth dial--effort low…max--effort low…max identical values — no translation needed
Where the mental models actually split

Identity & billing. Claude Code authenticates to Anthropic (subscription or API key) and runs Anthropic models. Copilot CLI authenticates to GitHub (OAuth or fine-grained PAT) and puts eight models from four vendors behind one subscription — with an Anthropic model as its documented default. Everything else — files, flags, hooks, skills — is dialect, not philosophy.

02

Config & Context Files

The question that started this guide — “where is CLAUDE.md in Copilot?” — has a two-part answer: copilot init writes .github/copilot-instructions.md, but Copilot also merges AGENTS.md, CLAUDE.md, and even GEMINI.md if they exist. All instruction files combine; there is no precedence order between them.

The migration that isn't

Copilot CLI treats .claude/skills/, .claude/agents/, .claude/commands/, and .claude-plugin/ manifests as first-class locations, and merges CLAUDE.md into instructions. A Claude Code repo is already a Copilot CLI repo. The reverse is not symmetric — Claude Code does not read .github/copilot-instructions.md or .github/skills/.

CLI Invocation & Flags

The flag dialects are close enough to bite: several flags are identical (--add-dir, --effort, --resume), a few translate cleanly, and two look alike but behave differently.

Interactive sessionclaudecopilot

False friends

--output-format json means a single result document in Claude Code but line-delimited JSONL in Copilot — pipe to jq -s if you need one array. Shift+Tab exists in both TUIs but cycles different wheels (section 04). And Copilot's --resume under -p without a TTY errors out rather than silently starting a fresh session.

Prompt prefixes & keys

!run a shell commandrun a shell command $ hands over the whole terminal (opt-in)

Muscle-memory hazard

Shift+Tab is the same reflex in both tools but steers different wheels: in Claude Code you're changing how much it may do without asking; in Copilot you're changing how it works — including autopilot, which keeps going without pausing for approval between steps. Double-Esc is the sharper trap: rewind menu in one, interrupt in the other.

The hook event map

Copilot's seven camelCase events all have a direct PascalCase counterpart in Claude Code. The reverse is very much not true — Claude Code documents 30 events, including permission, subagent, compaction, worktree, and config-change lifecycles with allow/deny/ask/defer decisions and input/output rewriting.

Copilot CLI eventClaude Code eventNote
sessionStartSessionStartdirect
sessionEndSessionEnddirect
userPromptSubmittedUserPromptSubmitdirect
preToolUsePreToolUseClaude adds allow/deny/ask/defer + input rewrite
postToolUsePostToolUseClaude adds output rewrite
agentStopStopfires when the agent finishes responding
errorOccurred—closest: PostToolUseFailure / StopFailure
—23 moreSetup, PermissionRequest, SubagentStart/Stop, PreCompact/PostCompact, WorktreeCreate/Remove, ConfigChange, FileChanged, Elicitation, …

Minimal hook, both dialects

claude · .claude/settings.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{
        "type": "command",
        "command": "just lint"
      }]
    }]
  }
}
copilot · .github/hooks/lint.json
{
  "version": 1,
  "hooks": {
    "postToolUse": [{
      "type": "command",
      "bash": "just lint",
      "timeoutSec": 60
    }]
  }
}

Copilot hooks have no per-tool matcher in the config — filter inside your script from the JSON stdin payload (toolName, toolArgs). Repo hooks in prompt mode need a trusted folder or GITHUB_COPILOT_PROMPT_MODE_REPO_HOOKS=true.

Permissions & Safety

Near-parity, with different persistence shapes: Claude Code scopes rules through its settings-file hierarchy; Copilot adds a per-location middle tier right in the approval dialog.

MechanismClaude CodeCopilot CLI
Per-tool approval prompt✓✓ y / n / ! allow-all-similar / # deny-all-similar
Session-scoped “always allow”✓✓ re-asks in new or resumed sessions
Per-location persistence◐ via settings-file scoping✓ “This location” tier, keyed to git root / directory
Config-persisted allow/deny rules✓ permissions.allow/deny✓ Kind(argument) patterns: shell(git:*), write(src/*.ts), url(…)
Deny beats allow✓✓ even under --allow-all
Read-only / plan mode✓✓
Yolo kill-switch for admins✓ managed settings✓ permissions.disableBypassPermissionsMode
OS sandbox for shell✓ Seatbelt (macOS), bubblewrap (Linux/WSL2)✓ /sandbox; MCP servers spawn sandboxed; + cloud sandbox
Env-var hardening◐ sandbox credential masking✓ blocks inline LD_*, DYLD_*, PATH, BASH_ENV assignments
Enterprise MCP allowlist◐ managed-mcp.json✓ fail-closed fingerprint check against policy endpoint
The yolo equivalence — and its leash

copilot --allow-all-tools is claude --dangerously-skip-permissions wearing a friendlier name — both give the agent your full shell. Both vendors also gave admins the same leash: a managed setting that disables bypass mode entirely, and in both tools deny rules survive yolo. If you script one, script the other with the same care.

07

Headless, CI & GitHub Actions

Both run headless with allowlisted tools. The strategic difference is auth: in GitHub Actions, Copilot can bill the org and authenticate with the workflow's built-in GITHUB_TOKEN — zero extra secrets. Claude Code answers with richer machine-readable output.

claude · headless with structured output
claude -p "Summarize this week's commits" \
  --allowedTools "Bash(git:*)" \
  --output-format stream-json \
  --include-partial-messages --verbose

# single-document result instead:
claude -p "…" --output-format json --json-schema schema.json
copilot · headless with allowlist
copilot -p "Summarize this week's commits" \
  --allow-tool 'shell(git:*)' \
  --output-format json -s

# JSONL out — one JSON object per line; collect with:
copilot -p "…" --output-format json -s | jq -s '.'

In GitHub Actions

claude-code-action · needs a repo secret
jobs:
  claude:
    runs-on: ubuntu-latest
    steps:
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
# setup: /install-github-app from a Claude Code session,
# then mention @claude in issues/PRs
copilot cli · built-in GITHUB_TOKEN
jobs:
  copilot:
    runs-on: ubuntu-latest
    steps:
      - run: |
          npm install -g @github/copilot-cli
          copilot -p "triage new issues" --allow-all-tools
        env:
          GITHUB_TOKEN: ${{ github.token }}
# zero extra secrets — org policy “billed to the organization”

08

Switching Gotchas

Six Claude Code habits, translated. The front of each card is the habit; flip it for what actually happens in Copilot CLI.

1
The habit
“My project rules live in CLAUDE.md”
Years of curated repo instructions, gotchas, and conventions in one file at the repo root.
In Copilot CLI
It just works — and then some
Copilot merges CLAUDE.md natively alongside AGENTS.md and .github/copilot-instructions.md. Careful: all instruction files combine with no precedence — contradictions between them become the model's problem.
2
The habit
“Shift+Tab until I'm in plan mode”
The reflex: cycle modes until the agent is read-only, then think out loud safely.
In Copilot CLI
Same key, extra stop on the wheel
The cycle is standard → plan → autopilot — and autopilot continues without approval pauses. One extra Shift+Tab past plan mode puts you in the most autonomous mode, not the safest. Copilot's own docs call plan mode “a safety net, not a guarantee.”
3
The habit
“I'll auth with a token in CI”
Drop an API key in the secrets store, export it in the workflow, done.
In Copilot CLI
Classic PATs are rejected
Copilot checks COPILOT_GITHUB_TOKEN → GH_TOKEN → GITHUB_TOKEN, and accepts fine-grained PATs only (with the “Copilot Requests” permission) — a ghp_ classic token fails. In Actions, skip PATs entirely: the built-in GITHUB_TOKEN works once the org policy is on.
4
The habit
“# saves a memory”
Old Claude Code reflex: prefix a line with # to stash a fact for later sessions.
In Copilot CLI
#123 pulls in an issue instead
# means GitHub reference: #123 loads that issue or PR into context. (At a permission prompt, # means “deny all similar”!) Memory needs no shortcut in either tool now — Claude's auto memory and Copilot Memory both just watch you work.
5
The habit
“Double-Esc opens the rewind menu”
Empty prompt, Esc Esc, pick a checkpoint, restore code and conversation.
In Copilot CLI
Esc Esc interrupts; type /undo instead
Double-Esc stops the running turn (and idle background agents). The checkpoint feature is /undo — alias /rewind, so your old command name still lands — with /session checkpoints to browse, and file tracking that works without git.
6
The habit
“My hooks gate every tool call”
PreToolUse matchers with JSON allow/deny/ask decisions enforce policy before anything runs.
In Copilot CLI
preToolUse exists — matchers don't
Copilot's preToolUse hook receives toolName/toolArgs as JSON on stdin, but there's no config-level matcher — your script filters. Port the policy logic into the script body, and lean on --deny-tool patterns for the hard guarantees (deny always wins).

What Copilot CLI Has That Claude Code Doesn't

The honest list — every item cited to a docs page in section 12. If you live inside GitHub's ecosystem, several of these are decisive.

AdvantageWhat it gives you
Multi-vendor model menuClaude, GPT, Gemini, and MAI models under one subscription — plus BYOK (COPILOT_PROVIDER_*) for your own endpoint. Switch mid-session with /model --session.
GITHUB_TOKEN auth in ActionsCI runs with the workflow's built-in token, billed to the org — no secret provisioning, no key rotation.
GitHub-native context#123 pulls issues/PRs into the prompt; /pr view|create|fix|auto|automerge drives a pull request to green from the terminal.
/delegate + cloud sandboxHand a task to the Copilot cloud coding agent, or run the whole session in an isolated cloud environment with copilot --cloud. Steer remotely from GitHub Mobile with /remote.
/rubber-duck & /fleetA second-opinion review agent that deliberately runs a complementary model, and parallel subagent fan-out as a built-in command.
Scheduled prompts/every and /after run prompts on a schedule or after a delay — recurring chores without cron.
Session sharing/share / --share-gist export a session transcript (even straight to a gist); --connect attaches to remote sessions.
First-class LSP config.github/lsp.json + /lsp test|logs|reload — code intelligence without writing a plugin.
Env-var hardeningInline LD_*/DYLD_*/PATH/BASH_ENV assignments in shell commands are blocked outright.
Fail-closed enterprise MCP allowlistServer fingerprints verified against a policy endpoint; unverifiable servers are blocked, not waved through.
Terminal quality-of-lifecopilot completion shell completions, /voice input, /theme, $ full-shell handoff, ACP server mode (--acp) for editor embedding.
The pattern

Copilot CLI's edge is the platform around the agent: GitHub identity, GitHub data, GitHub compute, many models. It competes less on agent internals and more on where the agent is plugged in.

What Claude Code Has That Copilot CLI Doesn't

The mirror list — the depth column. Claude Code's advantages cluster around programmability and documented control.

AdvantageWhat it gives you
The hook system30 documented events vs 7 — permission, subagent, compaction, worktree, and config lifecycles; JSON decision control (allow/deny/ask/defer); rewriting tool inputs and outputs; exit-code-2 blocking.
Agent SDKA real TypeScript/Python SDK for building custom agents on the Claude Code runtime — Copilot's closest analogue is ACP server mode plus JSONL parsing.
Structured output, properly--output-format json (single document) and stream-json, plus --json-schema for validated, typed results in scripts.
System-prompt control--append-system-prompt and three sibling flags; Copilot documents no system-prompt flag at all — you work through instruction files and custom agents.
Documented sandbox internalsSeatbelt on macOS, bubblewrap on Linux/WSL2, per-domain network proxy — auditable, and available standalone as @anthropic-ai/sandbox-runtime.
Auto memory with an indexPer-project memory directory with a MEMORY.md index loaded every session, browsable and editable via /memory — Copilot Memory exposes no equivalent surface.
Managed-settings depthFile + managed-settings.d/ drop-ins + MDM + server-managed, and managed-mcp.json — policy-as-files an enterprise can diff and deploy.
claude doctorOne diagnostics command for install health and settings validation; Copilot spreads this across help topics, logs, and /env.
Session plumbing--fork-session, --from-pr (resume the session tied to a PR), --fallback-model chains, --tmux worktree panes.
Plugin payload breadthPlugins can ship skills, agents, hooks, MCP servers, LSP servers, background monitors, and default settings in one bundle.
The pattern

Claude Code's edge is the agent as an engineering substrate: deeper events, richer machine output, documented internals, an SDK. It competes less on surrounding platform and more on how much of the agent you can program.
